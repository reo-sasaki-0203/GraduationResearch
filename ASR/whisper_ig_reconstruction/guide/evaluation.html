1. 評価する場所の対応表

評価入力と計算モデルのどこを使うかよい方向
音の近さWAVから再計算したメル・波形とcleanを比べるTransformerを使わず数値として測るMAE/RMSEは小、SI-SDRは大
文字起こし自由生成して正解文と文字編集距離を比べるEncoder→Decoder→選択・生成、その後は文字列処理CERは小、0で一致
固定文の出しやすさ同じ文脈・同じ次トークンの平均log確率Encoder→teacher forcing Decoder→logits→log_softmaxFは大（負の値なら0へ近い）

A=共通倍率のclean、B=mixture、C=再構成WAVです。評価する音声は別々に音量最適化しません。音の近さが上がっても、モデルが認識に必要とする成分を傷つければCERは悪化できます。

2. MAE・RMSE・メル相対誤差

各比較WAVを通常の前処理へ通して線形メルパワーを再計算します。cleanの有効フレームを共有し、同じPrefとfloorでdBへ変換します。計算上のマスク目標を、出来上がったWAVの代わりに主評価へ使いません。

Δ m,t = D(P out m,t ;P ref ) − D(P clean m,t ;P ref ) MAE = (1/K)∑ (m,t)∈valid |Δ m,t | RMSE = √((1/K)∑ (m,t)∈valid Δ m,t 2 )
\operatorname{MAE}=\frac1K\sum_{(m,t)\in\mathrm{valid}}|\Delta_{m,t}|
\operatorname{RMSE}=\sqrt{\frac1K\sum_{(m,t)\in\mathrm{valid}}\Delta_{m,t}^2}

Kは有効な時間×メル帯域セル数、mは帯域、tは時間フレーム。単位はdB差です。MAEは誤差の絶対値平均、RMSEは大きな誤差を二乗で重く扱います。dBの平均は、波形の平均や除去雑音の割合ではありません。

説明用：2セルの差が[−2,+4]dBならMAE=(2+4)/2=3dB、RMSE=√((4+16)/2)=√10≈3.162dBです。符号付き差は増えた／減った方向、絶対差はずれの大きさです。図の色範囲は同じ発話の比較で共有します。

linear_relative_error = ‖P out −P clean ‖ F / (‖P clean ‖ F +10 −15 ) ΔMAE = MAE(B)−MAE(C)
\Delta\operatorname{MAE}=\operatorname{MAE}(B)-\operatorname{MAE}(C)

線形相対誤差は対数前の表のずれを、cleanの大きさで割った無次元の値です。ΔMAEが正ならCの誤差が小さくなっています。clean最大から40dB以内／以下という補助領域もありますが、声と雑音の真の領域ラベルではありません。実装：db / metrics。

式のelinearはlinear_relative_errorと同じ値を表します。

3. SI-SDR：波形の形を、倍率を合わせて比べる

波形をそのまま引くと単なる音量差でも誤差が増えます。SI-SDRは出力波形のうちcleanと同じ向きの成分を取り出し、残りの誤差との比を測る尺度です。今回の実装は両方から平均を引いてから計算します。

s₀=s−mean(s), o₀=o−mean(o) β=⟨o₀,s₀⟩/(‖s₀‖²+ε), p=βs₀, e=o₀−p SI-SDR = 10 log 10 ((‖p‖²+ε)/(‖e‖²+ε)),　ε=10 −15
\beta=\frac{\langle o_0,s_0\rangle}{\|s_0\|^2+\varepsilon},\qquad p=\beta s_0,\quad e=o_0-p
\operatorname{SI\!\text{-}\!SDR}=10\log_{10}\!\left(\frac{\|p\|^2+\varepsilon}{\|e\|^2+\varepsilon}\right)
\varepsilon=10^{-15}

⟨·,·⟩は対応するサンプルを掛けて足す内積、‖·‖²は二乗和、pは出力のclean方向への射影、eは残差です。値が大きいほど波形の形が近いですが、聴感や認識精度を保証しません。時間のずれにも敏感で、ゼロ出力やほぼゼロのcleanには解釈上の注意が必要です。

説明用：平均0のs=[1,−1]、o=2sならβ≈2、残差≈0なので高い値になります。音量を2倍にした出力を「形が違う」と罰しないという意味です。ここでの射影は指標内の計算で、保存音声やモデル入力を別々に音量調整することではありません。定義の背景はLe Rouxらの原論文、数値安定化はsi_sdrで確認できます。

4. CER：文字列を合わせる最小の編集を数える

Whisperは各音声からgreedyで自由に文を生成します。正解文と出力文へ同じ正規化を掛け、文字列を一致させる最小編集を求めます。置換S、削除D、挿入Iを数え、正解文字数Nで割ったものがCERです。

CER = (S+D+I)/N

例えば正解「今日は晴れ」、出力「今日は雨」なら、「晴→雨」の置換1と「れ」の削除1でCER=2/5=40%です。説明用：「猫」に対して「猫犬犬」なら挿入2、N=1でCER=200%。CERは0〜100%に収まる確率ではありません。複数の最適な編集対応がある場合もあり、S/D/Iの内訳は採用した整列に従います。

今回の正規化はUnicode NFKC、空白とUnicode句読点カテゴリPの削除です。漢字を読みに変えたり同義語を正解へ寄せたりはしません。NFKCは文字幅などの互換表現をそろえます。生の文字列と正規化後を両方保存しています。CER=0はこの正規化後の一致で、話した意味や人の聞こえを完全に評価するものではありません。実装：normalize_text、compare_case、JiWER公式実装。

5. 発話平均とpooled CERは、重みが違う

短い発話も長い発話も同じ重さにする平均と、正解文字数の多い発話を重くする全体比率を別々に保存します。

mean utterance CER = (1/U)∑ u=1 U CER u pooled CER = (∑ u (S u +D u +I u ))/(∑ u N u )
\operatorname{CER}_{\mathrm{pooled}}=\frac{\sum_u(S_u+D_u+I_u)}{\sum_u N_u}

Uは評価可能な発話数、uは発話番号、Nuは各発話の正解文字数です。説明用：正解2文字で誤り1文字（50%）と、正解8文字で誤り1文字（12.5%）なら発話平均31.25%、pooled=2/10=20%です。失敗や打ち切りを誤り0にして分母へ足しません。今回のclear / mixture / reconstructedは1000件ずつ評価可能ですが、補助direct targetには別に失敗1件が残っています。

6. 固定文のF：同じ履歴から、同じ次トークンを測る

自由生成のclear / mixture / reconstructedは異なる文になり得るため、それぞれが出した別々の文の確率を比べると音声と文章の両方が変わります。teacher forcingは比較する文章のトークン列yを固定し、各位置までの正しい履歴をDecoderへ与える方法です。教師はここでは入力する履歴のことで、モデルを学習することではありません。

z j,v =Decoder(Encoder(X),y <j ) の語彙vのlogit p(y j |y <j ,X)=exp(z j,yj )/∑ v=1 V exp(z j,v ) F(X;y)=(1/L)∑ j∈text log p(y j |y <j ,X)
p(y_j\mid y_{<j},X)=\frac{e^{z_{j,y_j}}}{\sum_{v=1}^{V}e^{z_{j,v}}}
F(X;y)=\frac1L\sum_{j\in\mathrm{text}}\log p(y_j\mid y_{<j},X)

Xは音声の特徴、jはトークン位置、vは候補語彙ID、V=51866、zは確率にする前のlogit、Lは採点対象の文字トークン数です。logは自然対数です。Decoderへids[:-1]を入れ、logitsの各位置からids[1:]を採点する1位置シフトを使います。開始・言語・タスク・終了・時刻等は平均の対象から除外しますが、必要なprefixはDecoderの文脈として入力に残します。

log_softmaxと平均はfloat32で計算します。確率は内部logpからexpで求め、丸めた表示値で順位を決めません。自由生成時の抑制や探索で加工した確率と、固定文評価時の通常forward→log_softmaxは区別します。トークン分割の実例では、1語が1トークンとは限らず、単独decodeが文字として読めないbyte片を含むことも説明しています。

説明用・同じ2トークンを採点clearmixturereconstructed
1番目の対象トークンのp0.80.40.5
2番目の対象トークンのp0.50.50.8
平均logp F(ln0.8+ln0.5)/2≈−0.4581≈−0.8047≈−0.4581
exp(F)√0.4≈0.6325√0.2≈0.4472√0.4≈0.6325

exp(F)は各トークン確率の幾何平均です。文章全体の確率は（条件と特殊トークンの扱いを定義したうえで）積であり、上表の対象2個だけならA/Cは0.4です。幾何平均を正解率や全文確率と呼びません。Fは通常負で、大きいほどその同じ文を出しやすい値です。実装：score_sequences。

7. 正解文固定と、Bの文固定を分ける

主分析referenceはJSUT正解文を固定したclear / mixture / reconstructed比較、補助original_mixtureは保存されたBの生成列を固定した比較です。IGを作る対象は後者のmixtureの文です。正解文をマスク作成に使っていません。

順位ABCはFA>FB>FC。6種類の順序、同点、計算失敗を分け、差が1e−6以内なら近似同点とします。表示を丸めて同じに見えるかでは判断しません。トークンごとの確率差の横ばい許容差は1e−9で、Fの順位許容差とは別です。1発話の順位数と、多数のトークンの変化数を混同しないでください。

8. 今回の結果：改善の意味を取り違えない

保存済み結果では、平均CERはclear 6.94%、mixture 7.72%、reconstructed 8.76%。mixture→reconstructedは改善68、同じ742、悪化190件です。一方、平均メルMAEはmixture 16.404dBからreconstructed 13.215dBへ小さくなりました。メルの近さの改善と認識改善は一致していません。

正解文固定のFはreconstructedで上昇483件、低下517件、平均差−0.009046。スコアが上がったのにCERが悪化した例は35件あります。単一指標を「総合的に成功した割合」に置き換えません。

補助失敗sample_0400はdirect_target_mel/random_matchedで終了記号未取得です。自由生成の打ち切りをCER=0として扱わず、失敗理由を保持しています。IG数値品質の基準未達713件とは別の状態です。

1000件の検索・音声・全結果、CER集計CSV、スコアとCERの対応表から実測へ移動できます。

JSUTは1話者であり、5雑音群には異なる発話とSNRが入ります。結果を雑音種類だけの因果効果や全話者への一般的な結論にしないでください。対照・層別・bootstrapの解説へつながります。
