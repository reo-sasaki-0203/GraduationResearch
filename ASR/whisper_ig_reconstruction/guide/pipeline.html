今回の処理：SNRからIG95マスクまで

新しい言葉は、その処理が必要になる場面から導入します。1つの発話がA・B・Cになる過程と、モデル内部へ入る計算の境界を確かめます。

1. 異なる1000発話を、5条件へ割り当てる

今回のモデルはopenai/whisper-large-v3、版は06f233fe06e710322aca913c1bc4249a0d71fce1、IGは64近似点です。構造と詳細設定、実験設定を参照してください。JSUT basic5000から異なる1000発話（旧100件を含む）を使い、各発話には1種類の雑音を付けます。総数は5000ではありません。

雑音SNR発話数
white10dB200
pink10dB200
traffic0dB200
kitchen0dB200
river10dB200

乱数の種42を固定し、発話長で並べた5件ごとのブロックに5条件を1つずつ無作為に割り当てます。雑音群間は異なる発話なので、同じ発話に対する雑音種類だけの比較ではありません。clear / mixture / reconstructedは同一発話内の比較です。人工雑音は生成条件とseed、環境音は元ファイル・チャンネル・区間・倍率を保存しています。trafficの小さな人声らしき音への使用承認は、「完全な非音声雑音を確認済み」と同義ではありません。

2. なぜSNRが必要か：雑音の強さを再現できる条件にする

「雑音を少し足した」だけでは、次の実験で同じ条件を作れません。声に対して雑音がどれほど強いかを数値にするため、信号対雑音比（SNR）を導入します。ここで信号はcleanの声、雑音は混ぜるnoise_componentです。両方とも発話全区間の平均二乗パワーを使います。無音区間も含むので、発声中だけのSNRとは異なります。

SNR = 10 log 10 (P s /P n ) [dB] ;　α = √(P s / (P n,source · 10 SNR/10 ))
\alpha=\sqrt{\frac{P_s}{P_{n,\mathrm{source}}\,10^{\mathrm{SNR}/10}}}

Psはcleanの平均パワー、Pn,sourceは倍率を掛ける前の雑音パワー、αは雑音波形の振幅倍率です。倍率αを掛けるとパワーはα²倍なので平方根が必要です。10dBなら声のパワーが雑音の10倍、0dBなら等しいパワーです。「同じパワー」は耳で同じ大きさという意味ではありません。

説明用の数値声P=0.04、元雑音P=0.01の場合
10dBα=√(0.04/(0.01×10))=0.63246。混合する雑音パワー=0.004
0dBα=2。雑音パワー=0.04
SNRを10dB下げる雑音の振幅を√10≈3.162倍、パワーを10倍にする

説明用・同じ声と雑音の比だけを操作します

青＝元の声、橙＝倍率後の雑音、緑＝和。縦軸は3波形で共通です。モデルや保存WAVへ操作は行いません。

3. 共通音量倍率：AとBの関係を壊さない

まずx=s+αnを作ります。波形の値が大きすぎて音割れするのを避けるため、clean・倍率後雑音・mixtureのすべてへ同じgを掛けます。

g = min(1, 0.99 / max(max|s|, max|αn|, max|s+αn|, 10 −15 )) A=gs ;　noise_component=gαn ;　B=g(s+αn)=A+noise_component
A=gs,\qquad n_{\mathrm{component}}=g\alpha n
B=g(s+\alpha n)=A+n_{\mathrm{component}}

gは共通gain（倍率）で、max|·|は波形の最大絶対値です。共通倍率ならパワー比の分子・分母に同じg²が掛かるためSNRは変わりません。保存後の波形からSNRと加算関係を再確認します。Aを元の未調整録音と混同せず、B作成と同じ倍率のcleanとして比べます。ブラウザー再生用には別の共通倍率を使う場合がありますが、clear / mixture / reconstructedと差分だけを別々に最適化しません。実装：mix。

式のncomponentは、保存された雑音成分noise_componentと同じものです。

4. IGの対象：最終Encoder表現ではなく、固定した文章のスコア

Bを一度自由に文字起こしし、その実際のトークン列yBを固定します。入力XはBの128×3000のlog-Mel特徴です。対象Fは、固定したmixtureの文章の各文字トークンをモデルが出す対数確率の平均です。Fの詳細な計算とIGの定義を参照してください。

X：log-Mel順方向Encoder → Decoder
文脈yBを固定logits → log_softmaxF：1つのスカラー
各入力セルのIG勾配を逆向きに伝えるEncoder ← Decoder逆伝播の出発点固定文のF

モデル重みは凍結し、生成のargmaxを微分しません。毎回別の文を生成すると比較対象自体が変わってしまいます。IG作成にはJSUT正解文を使いません。追加clear / mixture / reconstructed分析では正解文固定とmixtureの文固定の両方を別集計しています。

5. 64回の内訳：基準から入力へ向かう積分の近似点

基準X⁰は、有効セルを無音波形から作った特徴へ置き換え、paddingはBの特徴のまま保持した表です。実装の無音特徴は−1.5ですが、paddingはすべて−1.5へ変えるわけではありません。組み立てた特徴空間の基準なので、単純な「完全な無音WAV」とも異なります。

X(a) = X⁰ + a(X−X⁰),　0≤a≤1 IG i = (X i −X⁰ i ) ∫ 0 1 ∂F(X(a);y B )/∂X i da IG i ≈ (X i −X⁰ i ) ∑ r=1 64 w r · ∂F(X(a r );y B )/∂X i
\operatorname{IG}_i=(X_i-X_i^0)\int_0^1\frac{\partial F(X(a);y_B)}{\partial X_i}\,da
\operatorname{IG}_i\approx(X_i-X_i^0)\sum_{r=1}^{64}w_r\frac{\partial F(X(a_r);y_B)}{\partial X_i}

iは時間×メル帯域の1セル、aは基準と入力の間の割合、arはGauss–Legendre積分の64点、wrは重みです。点も重みも単純な等間隔平均ではありません。各点でEncoder・Decoderを順方向計算し、その同じFから全入力セルの勾配を逆伝播して集めます。64回の新しい文字起こしでも、64回のモデル学習でもありません。internal_batch_size=1なので積分点をまとめた大きなバッチにはしません。

実装には、積分以外にも入力での勾配確認と、X・X⁰でのスコア確認があります。したがって、実際のforward呼出し総数がちょうど64という意味でもありません。モデルはbfloat16、入力・IG保持・スコア集約はfloat32を使う部分があります。数値品質も必ず確認してください。

「無音なら入力は0？」「基準は真っ黒？」「音声ごとに変わる？」はIG基準入力の詳しい説明、保存済み基準の可視化、入力への依存で確認できます。

6. 絶対重要度の累積95%：並べ替えから領域選択まで

95%は今回指定した探索条件です。最適な閾値だと証明された値ではなく、95%の声・文字・因果情報が残る保証もありません。signed IGが正なら固定Fを基準から入力へ変える方向の正寄与、負なら負寄与です。絶対値を使うと両方向の変化の大きさを残せますが、助ける／妨げる方向を区別できなくなります。

a i =|IG i | ;　T=∑ i∈valid a i a π(1) ≥a π(2) ≥… ;　K=min{k : ∑ j=1 k a π(j) ≥0.95T} M i =1 (iは上位Kセル), 0 (その他の有効セル) ;　paddingは1
a_{\pi(1)}\ge a_{\pi(2)}\ge\cdots
K=\min\!\left\{k:\sum_{j=1}^{k}a_{\pi(j)}\ge0.95T\right\}
M_i=\begin{cases}1&i\text{ is in the top }K\\0&\text{otherwise (valid)}\end{cases}
M_i=1\quad(i\in\mathrm{padding})

validは実発話のセル集合、πは重要度の降順へ並べた元のセル位置です。Kを決めたら元の場所へ戻してマスクMを作ります。同値はメル帯域を先、時間を後に並べたflatten indexによるstable sortです。連続した時間区間になるとは限りません。

説明用・2帯域×4時刻、絶対重要度の合計100

signed IG=[40,−25,15,−8,5,−4,2,−1]なら、絶対値の累積は40→65→80→88→93→97→99→100です。95に初めて届くのは6セルで、重要度は97%、保持面積は6/8=75%です。負の−25のセルも保持します。これが「絶対重要度の95%」と「面積の95%」の違いです。設定変更を行う操作ではありません。

今回のマスクは線形メルパワーPへ適用し、Ptarget=M⊙Pを作ります。⊙は対応セルごとの掛け算です。IGを求める座標Xと、音を削る座標Pを区別してください。対照のrandomとenergyは同じ保持セル数にそろえています。ranked_mask / make_masksに一致します。

7. 数値品質、処理完了、認識改善は別々に判定する

IGの符号付き和は、理想的な計算ではF(X)−F(X⁰)に対応します。有限回の積分・bfloat16等ではずれが生じるため、Captumのconvergence deltaを保存します。

δ = ∑ i IG i − (F(X)−F(X⁰)) relative_delta = |δ| / |F(X)−F(X⁰)|
\operatorname{relative\_delta}=\frac{|\delta|}{|F(X)-F(X^0)|}

分母が10−6未満ならrelative_deltaはnullです。今回の合格は|δ|≤0.01またはrelative_delta≤0.1。これは数値計算の運用基準で、認識が正しい証明ではありません。64点対128点のcosine・mask Jaccardは試行の安定性確認で、1000件全件を128点で置き換えたわけではありません。

1000件のうち品質合格287件、基準未達713件です。未達例も除外せず全件表へ残し、品質合格例だけの表を別に保存しています。IG精度不足、モデルの誤認識、再構成損傷をひとまとめの「失敗」にしないことが重要です。

8. 次に起きることと、保存されるもの

マスクされたメルパワーを、非負の近似逆変換・mixture位相・iSTFTでCのWAVへ戻します。再構成の章へ進んでください。その後、WAVから再計算する3種類の評価と差分C−B・B−Cを保存します。差分は雑音だけではなく、削れた声や逆変換誤差も含みます。

metadata.jsonには入力・条件、mixture_tokens.jsonにはBの固定トークン、attribution_metrics.jsonにはIG品質、mask_metadata.jsonには保持率、reconstruction_metrics.jsonには逆変換の停止理由、transcripts.jsonには実音声とdirect targetの認識、comparison.jsonにはclear / mixture / reconstructedの同じ対象列の比較を保存しています。対応コード一覧で追跡できます。
