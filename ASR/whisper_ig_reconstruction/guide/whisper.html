Whisper：音から文字までの道筋

音声を文字へ変える途中には、音の特徴、時間ごとの内部表現、文字の候補スコアという別々のデータがあります。今回のlarge-v3の実装を追い、それぞれを区別して理解します。

1. なぜEncoderとDecoderに分かれているのか

音声は連続する空気の振動、文字は離散的な記号です。両者には同じ数の要素が並ぶとは限りません。「あ」を長く伸ばしても文字数は増えず、短い音にも複数の文字が対応します。そこでWhisperは、音声を時間順の特徴にするEncoder（符号化器）と、その特徴を参照しながら記号を順に選ぶDecoder（復号器）を組み合わせます。Encoderは文章そのものを出力せず、DecoderもEncoderの各時間位置をそのまま1文字へ置換するわけではありません。

ASRはAutomatic Speech Recognition（自動音声認識）です。モデルが学習するのは、音声と文字列の対応を確率的に表す重みです。この実験では学習済み重みを固定し、学習や追加学習は行いません。入力の変更により認識や固定文のスコアがどう変わるかを測定しています。

波形 → log-Mel特徴 → 畳み込み → Encoder内部表現 → Decoder内部表現 → logits → 確率 → トークン列 → 文字列

EncoderとDecoderからなるWhisperの基本設計はWhisper原論文を参照してください。以下の層数や設定値は原論文掲載の旧モデルから転記せず、今回保存したlarge-v3の設定とローカル実装に照合しています。

2. 波形から128×3000の特徴へ

波形は時間ごとの振幅の列です。サンプリング周波数16,000 Hzなら1秒を16,000個の値で表します。今回の読込みは複数チャンネルを平均し、必要なら16 kHzへ再標本化します。2〜30秒の発話を選び、30秒未満は右側に波形の0を足して480,000標本にします。長い音声を黙って切り捨てる実装ではありません。

STFT（短時間フーリエ変換）は波形を短い窓ごとに周波数の成分へ分ける計算です。400標本＝25 msのHann窓を160標本＝10 msずつ進めます。窓を滑らかにすると、区間端の不連続を抑えられます。STFTは複素数で、振幅だけでなく波のずれである位相も持ちます。実装は3001フレームのSTFTを保持し、モデルの特徴には末尾1フレームを除いた3000フレームを使います。

メル尺度は周波数を人間の知覚に関連する間隔でまとめる尺度です。128個のフィルタで周波数パワーを加重集約し、線形メルパワーPを作ります。縦軸が128メル帯、横軸が3000時刻です。縦の番号をそのままHzと読むことはできません。

P m,t = Σ k H m,k |S k,t |² ℓ m,t = log 10 (max(P m,t ,10 −10 )) X m,t = (max(ℓ m,t , max m,t ℓ − 8) + 4) / 4
\ell_{m,t}=\log_{10}\!\bigl(\max(P_{m,t},10^{-10})\bigr)
X_{m,t}=\frac{\max(\ell_{m,t},\max_{m,t}\ell-8)+4}{4}

SはSTFTの複素数（201周波数×3001時刻）、Hはメルフィルタ（128×201）、Pはパワー（128×3000）、XはWhisper入力（128×3000）です。mはメル帯、tは時刻、kはSTFT周波数番号です。Xはこの前処理後の無次元値で、波形の振幅や線形パワーではありません。最大対数値から8下までに制限するため、あるセルの値は発話内の最大値にも依存します。

説明用の例：P=0.01ならlog₁₀P=−2、下限への丸めが働かなければX=(−2+4)/4=0.5です。P=0.0001ならX=0です。Xが0だから無音とは限りません。今回の入力には平均0・分散1へそろえる波形正規化を追加しておらず、公式FeatureExtractorとの照合もdo_normalize=Falseです。

詳細な波・窓・位相は音声の基礎、実装はaudio.py：MelTransformを参照してください。

3. 畳み込みとEncoder：形状を追う

畳み込み（convolution）は近くの時刻の特徴をまとめ、学習した重みで別の特徴へ変換する操作です。最初の畳み込みは時間幅3、stride（進む幅）1、padding（端に補う量）1で、128帯を1280特徴へ変換します。2段目は時間幅3、stride 2なので時刻数を半分にします。各段の後にGELUという滑らかな非線形変換が入ります。

段階形状（1発話）軸の意味
モデル入力1×128×3000発話×メル帯×10 msの時刻
畳み込み11×1280×3000発話×特徴×時刻
畳み込み21×1280×1500発話×特徴×約20 msの位置
軸の並替え＋位置情報1×1500×1280発話×音声位置×特徴
32層＋最終LayerNorm1×1500×1280Encoder最終内部表現

位置情報は「何番目の音か」を各位置の特徴へ足すものです。attentionだけでは順番を直接与えられないため必要です。ローカル実装のEncoder位置埋め込みは固定の正弦・余弦の表です。32層の各層には音声内self-attention、残差接続、LayerNorm、FFNがあり、層を重ねて文脈を含む特徴へ変えていきます。計算の詳細はTransformerの内部計算で説明します。

Encoderの1280個の特徴は「この番号が母音、この番号が雑音」と最初から名付けられた特徴ではありません。学習により得た数値の方向です。1500位置のうちpadding由来の位置も計算に入ります。有効区間のマスクを渡したから内部表現がすべて0になる、全attentionからpaddingが完全排除される、とは今回のeager Encoder実装から言えません。有効区間はIGの変更対象や評価範囲を定める別の役割も持ちます。

値と処理順はTransformers 4.51.3の実装と、保存済みmodel_info・固定版config.jsonに照合しました。

4. トークンとDecoder：文字数と要素数は異なる

トークンはモデルが扱う文字列の断片や制御記号です。必ず1文字・1単語とは限らず、日本語の1文字が複数トークンになることもあります。tokenizerは文字列とトークンIDの列を相互変換します。埋め込み（embedding）はIDを1280個の実数の表から引き、その記号を計算可能な特徴へ変える処理です。Decoderは学習された位置埋め込みも足します。

実際のtokenizerで確認した説明用文字列：「今日は晴れです。」は[43791, 5094, 112, 4132, 4767, 1543]です。43791が「今日は」、5094と112を組み合わせて「晴」、4132が「れ」、4767が「です」、1543が「。」に対応します。「晴」の片方のIDだけを文字へ戻すと不完全なバイト列なので置換文字になり得ます。トークン単位の寄与と文字単位の誤りを1対1に対応させない理由です。この例は実験の認識結果ではありません。

制御トークン今回のID役割
<|startoftranscript|>50258Decoderの開始
<|ja|>50266日本語指定
<|transcribe|>50360翻訳せず文字起こし
<|notimestamps|>50364時刻トークンを出さない
<|endoftext|>（EOS）50257生成終了
<|0.00|>50365時刻トークンの開始ID

今回の初期列は[50258,50266,50360,50364]です。他に翻訳・前の文章の文脈・無音などを示す制御記号がありますが、今回すべてを使用しているわけではありません。時刻IDは時間の対応を示す制御記号であり、普通の本文文字として扱いません。

Decoderの32層には、過去のトークンを参照するmasked self-attention、Encoderの音声特徴を参照するcross-attention、FFNなどがあります。未来の本文トークンを見て次のトークンを当てると不正な先読みになるため、self-attentionに因果マスクを使います。cross-attentionは各トークン位置から音声の1500位置を参照します。

5. 「出力」は6種類を区別する

名前今回の形状意味
Encoder最終内部表現1×1500×1280音声位置ごとの特徴
Decoder最終内部表現1×T×1280過去の記号と音声を統合した特徴
logits1×T×51866各位置で次の候補へ与える未正規化の値
確率1×T×51866候補方向へsoftmaxし総和1にした値
生成トークン列／文字列可変長候補の選択を繰り返した結果
固定文スコアF1発話につき1実数指定本文トークンの平均対数確率

TはDecoderへ与えるトークン位置数で、文字数ではありません。logitは正・負の任意の実数で、0.8だから確率80%という解釈はできません。最後の線形射影は1280特徴を語彙51866候補へ写します。

z j = W vocab h j p j,v = exp(z j,v ) / Σ u=1 51866 exp(z j,u )
p_{j,v}=\frac{e^{z_{j,v}}}{\sum_{u=1}^{51866}e^{z_{j,u}}}

hは最終Decoder特徴、Wは語彙への射影（51866×1280）、zはlogits、jは位置、v・uは候補IDです。softmaxは候補間の相対差を確率へ変えます。説明用の例：候補が3つだけでz=[2,1,0]ならp≈[0.665,0.245,0.090]です。現実の語彙数や実測値とは異なる例です。

IGの説明対象はEncoder最終層そのものではなく、Encoder・Decoder・語彙射影を通った固定文スコアFです。入力Xのセルに対する勾配を求めます。詳細はIG、スコア式やCERとの違いは評価指標を参照してください。

6. 自由生成とteacher forcingは違う計算

自由生成では、開始列と音声を与え、次の候補を選び、そのIDを前の列へ追加して再計算します。「今日は」の次にモデル自身が「雨」を選ぶと、その後も「雨」を含む履歴を条件に続きを生成します。今回のgreedyは1候補ずつ選ぶ方法ですが、未加工logitsの単純argmaxという説明だけでは不十分です。モデル由来のsuppress_tokensや開始時のbegin_suppress_tokensなど、生成時の候補制限が適用されるためです。begin_suppress_tokensには220とEOS50257が保存されています。

teacher forcingは評価したい文章をあらかじめ決め、過去の列もその文章にそろえて各次トークンの確率を計算します。これは毎回その文章を自由生成させる操作でも、モデルを再学習する操作でもありません。

説明用の整列：完成列が[開始,日本語,文字起こし,時刻なし,a,b,終了]なら、Decoder入力は末尾を除いた[開始,日本語,文字起こし,時刻なし,a,b]、正解候補は先頭を除いた[日本語,文字起こし,時刻なし,a,b,終了]です。位置3のlogitsはa、位置4はbを予測します。スコアの平均にはaとbを使い、制御記号・EOS・時刻は除きます。本文に句読点トークンがあればtoken_targetsでは除外せず、文字列CERの正規化とは処理が異なります。

固定文スコアでは、生成の候補抑制を経た分布ではなく、通常のforwardから得たlogitsをfloat32のlog_softmaxで計算します。モデル内部はbfloat16ですが平均対数確率の集約はfloat32です。自由生成が別の文を選んだとしても、固定した文を評価し続けるのでclear / mixture / reconstructedを同じ対象で比較できます。主IGではBで最初に生成した本文を固定し、追加の正解文評価とは区別します。

実装の対応箇所はasr.py：transcribe・token_targets・gather_text_score・scorerです。

この説明の位置番号は0から数えます。入力列を一つずらすことで、ある位置までのトークンから次のトークンの確率を評価します。

7. 今回の設定と、変更可能な設定

モデルはopenai/whisper-large-v3、固定revisionは06f233fe06e710322aca913c1bc4249a0d71fce1です。Transformersは4.51.3、精度bfloat16、attention実装eager、evalモード、重み固定、cache無効です。設定ファイルの古いtorch_dtype=float16という記述を、今回ロード時のbfloat16設定と混同しないでください。dropout確率は保存設定で0、SpecAugmentによる学習用の入力変形は採用していません。

日本語、transcribe、時刻出力なし、do_sample=False、num_beams=1、新規生成の上限440です。Decoderの位置上限は448で、今回の初期列4トークンと新規440はその範囲です。上限に達することとEOSで正常終了することは異なります。コードは末尾EOSのない結果を失敗として記録します。

設定何を変えるか今回／比較への影響
language・task言語と文字起こし／翻訳を指定ja・transcribe。変更すると評価する課題自体が変わる
num_beams複数の候補列を探索1。増やすと計算量・選択される文章が変わる
do_sample・temperature・top_k・top_p確率による抽選と候補分布の調整抽選なし。保存値temperature=1, top_k=50, top_p=1は今回のsampling動作を意味しない
max_new_tokens新しく作る要素数の上限440。位置上限を超えて自由に増やせない
repetition_penalty・no_repeat_ngram_size反復を抑える候補制限1・0。変更すると反復の頻度と確率選択が変わる
use_cache過去位置のK・Vを再利用False。速度・メモリ・実行経路に関係する
精度・attention実装数値の丸め方と計算経路bfloat16・eager。特に入力勾配や微小差にも影響し得る
return_timestamps・return_token_timestamps区間時刻やトークン時刻を取得不使用。本文認識と時間対応を別に検討できる
prompt_ids・condition_on_prev_tokens指定文や長時間音声の前区間を文脈として渡す今回の独立ケース間へ前の発話を持ち越さない
compression_ratio_threshold・logprob_threshold・no_speech_threshold長時間認識の反復・低確信・無音判断や再試行に関わる今回は独立した30秒以内の発話。この研究で採用した既定の処理と、追加設計を混同しない

利用可能な引数と条件は使用版のWhisper公式資料に確認できます。表は今後設計できる選択肢の説明で、変更の推奨や実施済み比較ではありません。teacher forcingで本文の過去を与えることと、別発話の文脈を引き継ぐことも異なります。

この説明の位置番号は0から数えます。入力列を一つずらすことで、ある位置までのトークンから次のトークンの確率を評価します。

8. 今回の研究で何を問うのか

研究では、A＝きれいな音声、B＝雑音を混ぜた音声、C＝IGに基づいてメル領域を保持し再構成した音声を比較します。Bの固定本文スコアに寄与した入力セルを可視化しても、そのセルが純粋な発話成分だと保証されるわけではありません。言語の文脈、モデルの非線形性、比較基準、音の再構成誤差が結果に関係します。

「音がAへ近づいた」「正解文のスコアが上がった」「自由生成のCERが下がった」は別々の問いです。どれか1つの改善だけを認識改善の証拠にしないでください。1000件主実験の条件と結果は処理の流れと評価の読み方へ進んでください。補助認識1件の失敗も保存された実験結果です。手引き作成によって認識条件や失敗の判定を変更していません。
